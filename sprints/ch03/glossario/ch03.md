# Glossário — Capítulo 3: Mecanismos de Atenção

Termos na ordem em que aparecem no capítulo.

---

**Attention Mechanism** — Mecanismo de Atenção: Permite à rede olhar para qualquer parte da sequência ao gerar cada token, em vez de depender apenas do token anterior. É o que faz os embeddings da Sprint 2 "conversarem" entre si.

**Self-Attention** — Autoatenção: Variante onde a sequência presta atenção nela mesma — cada token decide o quanto precisa de cada outro token da mesma frase para formar seu vetor de contexto.

**Attention Scores** — Pontuações de Atenção: Produto escalar entre dois tokens; valor alto indica que um token é relevante para o outro. São calculados antes do softmax.

**Attention Weights** — Pesos de Atenção: Resultado do softmax sobre os Attention Scores. Sempre positivos e com soma 1 por linha — interpretáveis como "quanto cada token contribui".

**Context Vector** — Vetor de Contexto: Saída da atenção para um token: soma ponderada dos vetores Value de todos os outros tokens, usando os Attention Weights. Carrega informação de contexto da sequência inteira.

**Query / Key / Value** — Consulta / Chave / Valor: Três projeções aprendidas de cada token. Query pergunta "o que procuro?", Key responde "o que tenho?", Value entrega "o que posso oferecer". Query × Key decide o peso; Value é o que é somado no Context Vector.

**Scaled Dot-Product Attention** — Atenção por Produto Escalar Escalonado: Os Attention Scores são divididos por √d antes do softmax. Sem isso, em dimensões grandes os scores ficam tão altos que o softmax satura e os gradientes somem.

**Causal Attention** — Atenção Causal: Mascara os tokens futuros substituindo seus scores por −∞ antes do softmax (resultado: peso 0). Garante que o modelo só veja o passado ao prever o próximo token — sem isso ele "trapacearia" durante o treinamento.

**Dropout**: Durante o treinamento, zera aleatoriamente uma fração dos Attention Weights. Evita que o modelo dependa demais de relações específicas entre tokens (overfitting). Desligado automaticamente em modo de avaliação.

**Multi-Head Attention** — Atenção Multi-Cabeça: Roda várias cabeças de atenção em paralelo, cada uma em um subespaço diferente, e concatena os resultados. Permite capturar ao mesmo tempo relações de tipos distintos (sintaxe, semântica, posição…).

**head_dim** — Dimensão por cabeça: `d_out / num_heads`. Cada cabeça opera nesse espaço menor; a concatenação de todas reconstrói a dimensão `d_out` original.

**MultiHeadAttentionWrapper**: Versão didática — cria `num_heads` instâncias de `CausalAttention` e concatena as saídas. Mais fácil de entender, menos eficiente.

**MultiHeadAttention**: Versão eficiente — usa uma única projeção Q/K/V e divide o resultado em cabeças via `view` + `transpose`. É essa que a Sprint 4 reutiliza no `TransformerBlock`.

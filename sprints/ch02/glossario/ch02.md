Tokenization / Tokenizer — Tokenização / Tokenizador: Processo de cortar o texto em pedaços menores, os tokens, e o componente que faz isso. É o primeiro passo entre o texto e o modelo, e o resultado é usado para montar o vocabulário. Pode ser simples, separando por espaços e pontuação, ou mais elaborado, como o BPE do GPT. Exemplo: "Hello, world." vira ["Hello", ",", "world", "."].

Token — mantém-se o termo em inglês: Cada pedaço de texto produzido pela tokenização: uma palavra, parte de uma palavra ou um sinal de pontuação. Todo o resto do pipeline trabalha com eles: cada token vira um Token ID e depois um embedding. Exemplo: o texto do capítulo, "the-verdict.txt" (20.479 caracteres), vira 4.690 tokens com o tokenizador por palavras.

Vocabulary — Vocabulário: Lista de todos os tokens diferentes que o modelo conhece, cada um com seu número. Funciona como um dicionário nos dois sentidos: token → número e número → token. Uma palavra que não está nele precisa virar um token especial ou ser quebrada em partes pelo BPE. Exemplo: o vocabulário do "the-verdict.txt" tem 1.132 entradas (1.130 tokens mais 2 especiais).

Token ID — mantém-se o termo em inglês: Número que identifica um token no vocabulário. É a forma como o texto entra no computador: o modelo nunca vê a palavra "gato", só o número dela. O ID é só um índice e não diz nada sobre o significado. Exemplo: no BPE do GPT-2, "Hello" é o ID 15496.

Special Context Tokens — Tokens Especiais de Contexto: Tokens extras colocados no vocabulário para situações especiais. O `<|unk|>` substitui palavras desconhecidas e o `<|endoftext|>` marca onde um texto termina e outro começa. Permitem que o tokenizador lide com qualquer texto sem dar erro. Exemplo: com um vocabulário montado a partir de "Firewall bloqueia ataques.", a frase "Firewall investiga ataques." vira "Firewall <|unk|> ataques.".

Byte Pair Encoding (BPE) — mantém-se o termo em inglês: Tokenizador usado pelo GPT-2 e pelo GPT-3 (biblioteca `tiktoken`) que quebra palavras raras em pedaços conhecidos. Por isso nunca precisa do `<|unk|>`: qualquer palavra, mesmo inventada, pode ser montada com pedaços. Tem um vocabulário bem maior (50.257 tokens) e costuma gerar mais tokens por frase. Exemplo: a mesma frase do livro deu 16 tokens com o tokenizador por palavras e 21 com o BPE.

Input-Target Pair — Par Entrada-Alvo: Uma sequência de Token IDs (entrada) e a mesma sequência andada uma posição para a frente (alvo). Ensina o modelo a prever o próximo token: para cada posição da entrada, o alvo é o token seguinte. Exemplo: entrada [40, 367, 2885, 1464] e alvo [367, 2885, 1464, 1807].

Sliding Window — Janela Deslizante: Forma de percorrer o texto para criar vários pares entrada-alvo: uma janela de tamanho fixo anda pelo texto, alguns tokens por vez. É o que o `GPTDatasetV1` faz para transformar um texto inteiro em várias amostras de treino. Depende do Context Size (tamanho da janela) e do Stride (tamanho do passo).

Context Size / Context Length — Tamanho de Contexto: Quantos tokens o modelo vê de uma vez em cada amostra. É o tamanho da janela deslizante. Quanto maior o contexto, menos amostras o mesmo texto rende. Exemplo: com o "the-verdict.txt" em BPE (5.145 tokens), contexto 2 gerou 2.572 amostras, e contexto 32 gerou só 160.

Stride — Passo: Quantos tokens a janela deslizante anda de uma amostra para a próxima. Controla a repetição entre amostras: passo igual ao contexto não repete nada, e passo menor gera mais amostras, mas com tokens repetidos. Exemplo: com contexto 32, passo 8 gerou 640 amostras (75% repetidas) e passo 32 gerou 160 (sem repetição).

Embedding Layer — Camada de Embedding: Camada do PyTorch (`torch.nn.Embedding`) que funciona como uma tabela: recebe um Token ID e devolve a linha correspondente, um vetor de números. Os valores começam aleatórios e são ajustados no treino. O tamanho da tabela é o tamanho do vocabulário vezes a dimensão do vetor. Exemplo: com o vocabulário do BPE (50.257) e vetores de 256, a tabela tem 12.865.792 parâmetros.

Token Embedding — Vetor de Representação do Token: O vetor que a camada de embedding devolve para cada Token ID. Troca um número sem significado por uma lista de números que o modelo pode ajustar para representar o sentido do token. É a ideia de Embedding do Capítulo 1 aplicada na prática. Exemplo: um lote de 8 sequências de 4 tokens, formato (8, 4), vira (8, 4, 256) com vetores de 256.

Positional Embedding — Vetor de Representação de Posição: Vetor que representa a posição do token na frase (0, 1, 2, ...), e não o token em si. É necessário porque a atenção da Sprint 3 não sabe a ordem das palavras. O projeto usa posições absolutas, como o GPT original. Exemplo: o mesmo token nas posições 0 e 1 só fica com vetores diferentes depois de somar o positional embedding.

Input Embedding — Vetor de Entrada do Modelo: A soma do token embedding com o positional embedding: junta "qual é o token" com "onde ele está". É o que entra na primeira camada do Transformer, a atenção da Sprint 3. Tem o mesmo formato do token embedding. Exemplo: (8, 4, 256) para um lote de 8 sequências de 4 tokens.

Dataset — mantém-se o termo em inglês: Classe do PyTorch (`torch.utils.data.Dataset`) que guarda as amostras e diz como pegar uma delas e quantas existem. No projeto, o `GPTDatasetV1` guarda os pares entrada-alvo criados pela janela deslizante. Exemplo: o "the-verdict.txt" com contexto 8 e passo 8 rende 586 amostras.

DataLoader — mantém-se o termo em inglês: Componente do PyTorch (`torch.utils.data.DataLoader`) que pega as amostras do Dataset e as entrega em lotes, podendo embaralhar e descartar o último lote incompleto. Liga a preparação dos dados ao treino: os lotes que ele entrega (ainda em Token IDs) passam pela camada de embedding e depois pelo modelo. Exemplo: 5 amostras em lotes de 2 dão 3 lotes, ou 2 se o último incompleto for descartado.

Batch / Batch Size — Lote / Tamanho do Lote: Grupo de amostras processadas juntas pelo modelo, e quantas amostras cabem nele. É definido no DataLoader e muda só a primeira dimensão dos tensores, sem mexer no contexto nem no tamanho do embedding. Exemplo: lotes de 8 com contexto 4 têm formato (8, 4).
